## 1. 概要

### 1.1 プロダクト

日本の伝統文化である錦鯉の美しさを、3D 空間で体験・継承するシミュレーター。育成ゲームそのものより、「生きた芸術」としての模様・色彩の再現と、交配・品評といった文化的文脈の体験に重点を置く。

## 2. コンセプトと非目標

### 2.1 目標

- 錦鯉らしい地色・緋・墨の重ねを、手続き的ノイズとシードで個体差として表現する。
- ユーザーが「作る / 掛け合わせる / 眺める」循環で、自分だけの個体を残せるようにする。
- 水面・コースティクス・遊泳モーションで、池を眺める体験の質を上げる。

### 2.2 非目標（現時点）

- オンライン対戦、課金、マルチプレイ。
- 生物学的に厳密な遺伝モデル（現行交配はパラメータの乱択・線形補間）。
- ビルド済みプレイヤー単体でのアセット保存（Editor 専用 API に依存）。

## 4. システム構成

```
KoiScene
  SelectManager          … タブ切替（交配 / 新規作成 / 編集）
  BreedingUIManager      … 親選択・交配実行・子の保存
  KoiEditorManager       … スライダー・カラーピッカー・モード・保存
  KoiPhotoStudio         … オフスクリーン撮影キュー
  KoiController          … PatternData → MaterialPropertyBlock
  ObjectRotator          … 作成画面のモデル回転

IkeScene
  KoiSpawner             … Assets/KoiData を読み、プレハブを放流
  KoiNaturalTurn         … 視界内遊泳・回避・バンク
  KoiGrowthController    … 成長・コンディション・密度によるスケール
  KoiRippleEmitter       … 遊泳に応じた波紋インパルス
  RippleSimulator        … 水面高さフィールドの ping-pong シミュレーション
```

データ実体はすべて `KoiPatternData`（`Assets/KoiData/*.asset`）。見た目はマテリアルを複製せず、`MaterialPropertyBlock` で個体ごとに squish する。

## 5. データ仕様

### 5.1 KoiPatternData

メニュー: `Create > Koi > PatternData`  
クラス: `KoiPatternData`（`Assets/Script/KoiPatternData.cs`）

| フィールド | 型 | 意味 |
|------------|----|------|
| `mainColor` | Color | 地色（メイン） |
| `sub1Color` | Color | サブ色 1（典型的には緋） |
| `sub1Scale` | float | サブ 1 模様のスケール |
| `sub1Amount` | float | サブ 1 の出現量（0 で実質オフ） |
| `sub1Detail` | float | サブ 1 のディテール |
| `sub2Color` | Color | サブ色 2（典型的には墨） |
| `sub2Scale` | float | サブ 2 模様のスケール |
| `sub2Amount` | float | サブ 2 の出現量 |
| `sub2Detail` | float | サブ 2 のディテール |
| `patternSeed` | Vector3 | ノイズオフセット。個体差の核 |
| `bellyLimit` | float | 腹側の白残り境界（-0.5〜0.5） |
| `photoTexture` | Texture2D | サムネイル。保存時にアセットへ埋め込む |

ファイル名（ScriptableObject の `name`）が個体名として UI に出る。

### 5.2 保存場所

- ディレクトリ: `Assets/KoiData/`
- 拡張子: `.asset`
- リポジトリ上の例: 紅白、大正三色、昭和三色、山吹黄金、プラチナ、緋写り、白写り など

同名ファイルがある場合、新規保存は `名前 1.asset` のように連番を付ける。

### 5.3 シェーダーとの対応

シェーダー: `Custom/URP_Koi_Pattern_Managed`（`Assets/URP_Koi_Pattern_Managed.shader`）

`KoiController.ApplyDNA()` が PropertyBlock に載せる主なプロパティ:

| シェーダー | データ |
|------------|--------|
| `_MainColor` | `mainColor` |
| `_SubColor1` / `_Sub1Scale` / `_Sub1Amount` / `_Sub1Detail` | サブ 1 |
| `_SubColor2` / `_Sub2Scale` / `_Sub2Amount` / `_Sub2Detail` | サブ 2 |
| `_Seed` | `patternSeed` |
| `_BellyLimit` | `bellyLimit` |

シェーダー側の光学パラメータ（フレネル、イリデッセンス、コースティクス配列など）は個体データではなくマテリアル共通の質感として扱う。

## 6. 機能仕様

### 6.1 作業画面のタブ（SelectManager）

起動時は交配タブを開く。

| 操作 | 挙動 |
|------|------|
| 交配 | `crossPanel` を表示。作業用 3D モデルは非表示。 |
| 新規作成 | `editorPanel` を表示。回転エリアとリセットボタンを出す。`KoiEditorManager.ResetToNew()`。 |
| 編集 | `selectPanel` を開き、`BreedingUIManager.OpenForEditMode()` で個体リストを出す。選択確定後はエディタパネルへ遷移。 |

アクティブタブのボタンは `interactable = false` とし、色を `activeTabColor` にする。

### 6.2 詳細作成・編集（KoiEditorManager）

#### 色モード

| モード | 意味 | シェーダーへの適用 |
|--------|------|--------------------|
| Single | 単色 | `_Sub1Amount = 0`, `_Sub2Amount = 0` |
| Dual | 2 色 | サブ 1 のみ有効 |
| Triple | 3 色 | サブ 1・サブ 2 とも有効 |

モード切替で、不要なスライダーとカラーボタンを隠す。起動直後の既定は `SetModeSingle()`。既存アセット読込時は `sub2Amount` / `sub1Amount` の閾値（0.01）でモードを自動判定する。

#### パラメータ UI

- スライダー行は `EditorSliderRow` プレハブを動的生成する。
- 詳細トグル（`seedToggle`）OFF のときは RGB スライダーとシードスライダーを隠す。通常はカラーボタン + 量・大きさ・詳細。
- カラーピッカー: HSV 色相環テクスチャ（128px）を実行時生成。明るさは別スライダー。色相は `savedHues` に保持し、明るさ変更で黒潰れしない。

#### 乱数

- `RandomizeSeedOnly`: `_SeedX/Y/Z` のみ 0〜100。
- `RandomizeAll`: 全スライダーをそれぞれの min〜max で乱数。

#### 保存

- Unity Editor のみ（`#if UNITY_EDITOR`）。
- 新規: `CreateAsset`。編集中アセットがある場合は上書き。名前変更時は `RenameAsset`。
- 保存直前に `KoiPhotoStudio` が RenderTexture から `Texture2D` を読み、`photoTexture` としてサブアセット化する。
- 旧サムネイルサブアセットは削除してから差し替える。

#### 3D プレビュー

`targetKoi` 配下の全 Renderer に PropertyBlock を毎更新。`ObjectRotator` は指定パネル上でのドラッグのみ回転し、リセットで初期姿勢に戻す。

### 6.3 交配（BreedingUIManager）

クラス名は `BreedingUIManager`、ファイル名は `BreedingManager.cs`。

#### フロー

1. 親 1 / 親 2 ボタンで選択パネルを開く。
2. `Assets/KoiData` 内の `KoiPatternData` をリスト化（`KoiListButton`）。写真が無ければスタジオ撮影。
3. 確定すると 3D モデルに DNA を適用し、対応 RenderTexture を RawImage に出す。
4. 両親が揃うと交配ボタンが有効。
5. 交配実行後、子プレビューと誕生パーティクル。保存ボタンが有効。
6. 名前入力（空なら「名無しの錦鯉」）して保存し、UI をリセット。

#### 遺伝ルール（現行）

色（`mainColor`, `sub1Color`, `sub2Color`）と `patternSeed` のベースは、親 1 / 親 2 から 50% で一方を選ぶ。

シードには追加で各軸 -5〜+5 のジッター（Z は 0）を加える。

量・スケール・ディテールは、乱数 `blendRate`（0.3〜0.7）による線形補間。

`bellyLimit` は両親の平均（補間 0.5）。

15% の確率で突然変異相当: `sub1Amount` と `sub2Amount` を 0 にし、単色化する。

子データはメモリ上の ScriptableObject。保存するまでアセット化されない。

#### 編集モードとの共用

選択ターゲット `0` は編集用。リスト確定時は `KoiEditorManager.LoadAssetForEdit` を呼び、`SelectManager.OnClickEditorButton` でエディタへ移る。

### 6.4 池での飼育表示（IkeScene）

#### スポーン（KoiSpawner）

Start 時に Editor 限定で `Assets/KoiData` を全ロードし、各データにつきプレハブを 1 体生成。`KoiController.patternData` をセットして `ApplyDNA()`。

生成位置: Main Camera の視界円錐を水面高さ Y=1.0 で切った矩形の 70% 内側。向きは Y 軸 0〜360° 乱数。

#### 遊泳（KoiNaturalTurn）

ファイル: `KoiRandomMove.cs`。クラス名は `KoiNaturalTurn`。

- カメラ視界の 70% を遊泳範囲とし、個体ごとの閾値で内側へ向きを戻す。
- Tag `Koi` の他個体が前方視野（距離 1.5、角度 110°）に入ると段階減速（貫通軽減）。
- 間欠的な弱い加速、休息、深度オフセット、バンク・ピッチ。
- 数秒ごとに進行方向を ±25° 程度ランダム変更。

#### 成長（KoiGrowthController）

`[ExecuteAlways]`。インスペクター操作でも即時反映。

| パラメータ | 範囲 | 効果 |
|------------|------|------|
| `growth` | 0〜1 | 体長方向スケール |
| `condition` | 0〜1 | 体幅（0.8〜1.4 倍） |
| `density` | 0〜1 | 環境係数（0.5〜1.0）。成長量に乗算 |

体が伸びると模様 UV スケールも逆算で補正し、模様位置が体サイズでずれないようにする。  
給餌・時間経過・水質といったゲームループは未接続。パラメータは手動調整用。

### 6.5 水面・波紋

名前空間 `KoiPond`。

- `RippleSimulator`: 2 枚の RenderTexture で波動を ping-pong。減衰・速度・ステップ数を持つ。結果を水面マテリアルの `_RippleTex` 等へ供給。
- `KoiRippleEmitter`: 速度に応じた船首波、尾びれ、跳ね、体の押し退けを `AddImpulse`。
- 関連シェーダー: `KoiPondWater`, `RippleSim`, `PondBottom`, コースティクス配列ビルダー。

クレジット: コースティクス画像は OpenGameArt（CC0）、HDRI は Poly Haven Mossy Forest（CC0）。詳細はリポジトリ README。

### 6.6 品評会・ショップ

シーンはビルドに含まれるが、評価ロジック・出品フロー・購入フローの仕様実装は無い。将来拡張枠。

## 7. UI / UX 仕様

### 7.1 交配画面

- 親 1・親 2・子の 3 スロット。未選択時はプレースホルダ文言とグレー画像。
- 選択後は個体名をスロット下に表示。
- 交配ボタンは両親確定まで無効。保存は子生成まで無効。

### 7.2 リストボタン（KoiListButton）

名前とプレビュー画像。クリックでマネージャーへ選択通知。確定ボタンはリスト項目選択まで無効。

### 7.3 カラーピッカー

クリック / ドラッグで色相・彩度を決定。円外は彩度 1 にクランプ。明るさはグループ内スライダー。

## 8. 技術的制約と既知のギャップ

### 8.1 Editor 依存の永続化

次は `#if UNITY_EDITOR` + `AssetDatabase` 前提である。スタンドアロン / モバイルビルドでは個体の列挙・保存が動かない。

- `BreedingUIManager` のリスト読込と子の `CreateAsset`
- `KoiEditorManager.SaveAsAsset` / `FinalizeSave`
- `KoiSpawner.LoadAllPatternAssets`

ランタイム化する場合は Addressables、JSON、ScriptableObject の Resources 配置、または独自セーブへの置き換えが必要。

### 8.2 SceneLoader のシーン名

`sceneName` は Editor の `Awake` でのみアセット名から埋まる。ビルドではシリアライズされた `sceneName` が空のままだと遷移に失敗する。ビルド対応時はシーン名文字列のシリアライズが必要。

### 8.3 クラス名とファイル名の不一致

| ファイル | クラス |
|----------|--------|
| `BreedingManager.cs` | `BreedingUIManager` |
| `KoiRandomMove.cs` | `KoiNaturalTurn` |

### 8.4 パフォーマンス

`KoiNaturalTurn` は毎フレーム `FindGameObjectsWithTag("Koi")` する。個体数が増えるとコストが線形以上に増える。

### 8.5 エディタ保存の失敗系

編集モードで、既存の別ファイルと同名にリネームすると `RenameAsset` が失敗しうる（コード上のコメントどおり）。ユーザーへのエラー表示は未整備。
