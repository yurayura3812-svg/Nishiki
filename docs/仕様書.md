## 4. シーンとクラス

```
IkeScene
  KoiSpawner             … Assets/KoiData を読み、プレハブを放流
  KoiNaturalTurn         … 視界内遊泳（ファイルは KoiRandomMove.cs）
  KoiGrowthController    … スケール。企画の成長機能ではない
  KoiRippleEmitter       … 波紋
  RippleSimulator        … 水面シミュレーション

KoiScene
  SelectManager          … タブ（交配 / 新規作成 / 編集）
  BreedingUIManager      … 親選択・交配・子の保存（ファイルは BreedingManager.cs）
  KoiEditorManager       … スライダー・カラーピッカー・保存
  KoiPhotoStudio         … サムネイル撮影
  KoiController          … PatternData → MaterialPropertyBlock
  ObjectRotator          … モデル回転
```

遷移は `SceneLoader`。Editor ではシーンアセット名から名前を取る。ビルドでは名前のシリアライズが必要。

## 5. データ（実装）

### 5.1 現行: KoiPatternData

`Assets/Script/KoiPatternData.cs`  
メニュー: `Create > Koi > PatternData`  
保存先: `Assets/KoiData/*.asset`

| フィールド | 型 | 意味 |
|------------|----|------|
| `mainColor` | Color | 地色 |
| `sub1Color` / `sub1Scale` / `sub1Amount` / `sub1Detail` | | サブ 1（緋など） |
| `sub2Color` / `sub2Scale` / `sub2Amount` / `sub2Detail` | | サブ 2（墨など） |
| `patternSeed` | Vector3 | 模様の個体差 |
| `bellyLimit` | float | 腹の白残り |
| `photoTexture` | Texture2D | サムネイル |

個体名はアセットの `name`。企画の個体ID・品種・艶・親ID・体型は未所持。

### 5.2 企画項目とのギャップ

| 企画 | 現状 |
|------|------|
| 個体ID | なし（ファイル名） |
| 品種 | なし |
| 模様データ | 上記フィールド |
| 体型データ | なし（`KoiGrowthController` は別物） |
| 艶 0〜100 | なし。シェーダーのコート／グアニンへ載せる想定 |
| 親個体ID | なし |
| 交配履歴・品評記録 | なし |

同名保存時は `名前 1.asset` と連番。

### 5.3 シェーダー

エントリ: `Custom/URP_Koi_Pattern_Managed`  
分割: `Assets/Shader/KoiCommon.hlsl` / `KoiPattern.hlsl` / `KoiLighting.hlsl`

`KoiController.ApplyDNA()` が載せる値:

| シェーダー | データ |
|------------|--------|
| `_MainColor` | `mainColor` |
| `_SubColor*` / `_Sub*Scale` / `_Sub*Amount` / `_Sub*Detail` | サブ色 |
| `_Seed` | `patternSeed` |
| `_BellyLimit` | `bellyLimit` |

光学（コート、グアニン）はマテリアル側。艶パラメータ接続はこれから。

鱗の UV マス目による凹凸は入れない。テクスチャに描いた鱗を使う。

## 6. 現行の動き

### 6.1 交配（BreedingUIManager）

1. 親スロットからリストを開く  
2. `KoiData` を列挙。写真が無ければスタジオ撮影  
3. 両親が揃うと交配可能  
4. 子プレビューのあと名前を付けて保存（空なら「名無しの錦鯉」）

**遺伝（現行）**

- 色と `patternSeed` のベースは親から 50% で一方を選ぶ  
- シードに X/Y 方向 -5〜+5 のずれ（Z は 0）  
- 量・スケール・ディテールは `blendRate` 0.3〜0.7 で補間  
- `bellyLimit` は平均  
- 15% でサブ量を 0 にして単色化  

これが企画 4.2 の「模様の決まり方」の現行実装である。

### 6.2 作成・編集（開発用）

Single / Dual / Triple。スライダーとカラーピッカー。Editor のみ保存。

### 6.3 池

Start 時に `KoiData` を全ロードしてスポーン（Editor 限定）。視界の 70% 内側。`Koi` タグ同士で減速。

### 6.4 水面

`KoiPond`。`RippleSimulator` と `KoiRippleEmitter`。コースティクスは OpenGameArt（CC0）、HDRI は Poly Haven Mossy Forest（CC0）。

## 7. 制約

- 個体の列挙・保存・スポーンが `#if UNITY_EDITOR`。ビルドでは残らない。JSON 等への置き換えが必要。  
- `SceneLoader` のシーン名が Editor の Awake 依存。  
- ファイル名とクラス名のずれ: `BreedingManager.cs` → `BreedingUIManager`、`KoiRandomMove.cs` → `KoiNaturalTurn`。  
- `KoiNaturalTurn` は毎フレーム `FindGameObjectsWithTag("Koi")`。  
- 縁が黒く見える問題: 横向き面で光が消える計算。コートの F 上限・影の下限・反射の上向き補正を入れている（作業中）。

## 9. 実装のこれから（優先順）

企画の体験に必要な順。成長ループは載せない。

1. ランタイム保存（`feature/runtime-save`。persistentDataPath の JSON）  
2. SCR-02 を一覧＋交配に揃える。池（SCR-01）からの入口  
3. 個体ID・親ID・生成日時。艶 0〜100 をデータとシェーダー（コート／グアニン）へ接続  
4. 池に出す個体の選択（全スポーンをやめる）  
5. エサやり（口アニメ、サイズ不変）  
6. 品評（模様・体型・艶）。体型データの中身を先に決める  
7. 池カスタム  
8. 質感シェーダーが安定したら `main` へ載せる  
9. `SceneLoader` のビルド対応
